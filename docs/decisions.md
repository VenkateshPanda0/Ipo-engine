## D-003 — PDF stack: pdfplumber + pypdfium2; no PyMuPDF (2026-10-19)

## D-006 — Page and unit model (2026-10-19)

- Every block/table carries a 1-based `pdf_page` (physical page). The printed page label is stored
  separately as `printed_page`, best-effort, and is never used for citations.
- Downstream text is rendered with parser-injected `[PDF_PAGE_N]` tags; page numbers are never
  inferred from page text.
- Units (rupees, thousand, lakh, million, crore, billion) are detected per table from the caption
  above it or its first rows, and stored on the table with the matched text. Values are not
  converted in M0. Conversion helper `to_rupees` exists and is tested.
- No OCR in M0. Pages with no text layer but with images are flagged `needs_ocr` and reported.

## D-011 — Fetcher integrity rules, from real downloads (2026-10-21)

Both SEBI PDFs were silently truncated by the first fetcher. Rules now: compare received bytes with
the announced length, resume with HTTP Range (bounded retries, restart if the server ignores Range),
require `%%EOF`, and treat a cached file that fails these checks as missing. Alternative considered:
trusting the manifest hash alone; rejected, because a hash of a truncated file is still a valid hash.

## D-015 — Rules are TOML specs with validity windows (2026-10-23)

Each rule is a data file naming its logic type, thresholds, platforms, `valid_from`/`valid_to`,
and its sources (ICDR clause, effective date, date checked against SEBI's consolidated copy
"Amended upto March 21, 2026"). A superseded threshold is kept as a separate `-PRE2025` rule so a
2024 filing is judged by 2024 law. Heuristic rules say so and cite the literature. Alternative
considered: thresholds in Python; rejected because the audit trail (clause + date) must live next
to the number.

## D-016 — Label-free correctness checks come first (2026-10-23)

Because hand labels are scarce, three checks need none and run on every document: (1) each cited
value is re-read from the PDF text layer through a different code path; (2) accounting identities
foot (total income = revenue + other income; PAT = PBT - tax; assets = equity + liabilities);
(3) independent tables agree (consensus). A value that fails (1) is never reported. (2) and (3)
are signals, not proof; the benchmark (D-018) is the measurement.

## D-017 — Consensus prefers columns that foot (2026-10-24)

Repetition is not evidence: three cash-flow tables printing "profit before tax" before the share
of an associate (2,239.30) outvoted the P&L's 2,239.15. Readings from (table, period) columns whose
own identities foot are preferred to any number of readings from columns that cannot be checked;
trust is per column because one year printed with a different sign convention must not discredit
the years that foot. Within an agreeing cluster the exact figure most tables print is reported.

## D-018 — Benchmark scoring and its honest limits (2026-10-24)

A prediction is correct when it is within the coarser printed precision of the label (so 538.02
vs 538.03 agree, 2,239.30 vs 2,239.15 do not). Citation accuracy requires the cited page to be one
where the labeller found the statement. Labels were written by the maintainer, an AI, reading
poppler text (a different extraction path); there is no inter-annotator agreement. The first six
filings are a development set: the extractor was tuned against them, so their scores overstate
generalisation. A held-out set (D-021) was added to measure that.

## D-022 — The report is one self-contained HTML page (2026-10-24)

`rh report` writes one page per filing: flags with evidence, issue and objects, annual figures in
₹ crore, what could not be checked, figures withheld because tables disagree, how far to trust the
extraction. No script, no external resource; every figure links to `#page=N` of the source PDF; all
text from the document is HTML-escaped (tested with hostile input). "No flags" is worded as "not a
clean bill of health" with the count of rules that could be evaluated, because zero flags is mostly
missing inputs. Rules that never applied (other platform, not yet in force) are collapsed so they
do not read as gaps.

## D-023 — Rules that do not fit a business are not applied (2026-10-24)

The cash-flow-below-profit heuristic fired on a lender and a developer, for whom negative operating
cash flow is structural (loan book, inventory). A rule may list `not_for_sectors`; sectors come from
counting self-description in the first 150 pages (lender: NBFC / housing finance wording at least
30 times; real estate: RERA / project wording at least 30 times). Thresholds were set on nine
filings (lenders 61 and 126 mentions, a payments company 15, a developer 9 NBFC mentions). The
exclusion is shown in the report and the rule audit as "not applied to this kind of business".

## D-024 — ICDR 2018 rules start on 10 Nov 2018 (2026-10-24)

A December 2005 draft was being judged by 2018 thresholds because several rule files had no start
date. They now start when the regulations came into force (gazette 11 Sep 2018 plus 60 days; the
consolidated SEBI copy omits the date, so it rests on secondary sources, noted in each rule file).
Rules for periods before that are not written: the predecessor regulations (2009) are a separate
primary text that has not been read.

## D-027 — Text a reader cannot see (2026-10-24)

The text layer is what the extractor reads, but a reader sees what is drawn. Characters under one
point or wholly off the page are dropped; white characters with no coloured shape, curve or image
behind them are kept (white on a coloured header is normal) and counted. A page with 15 or more
such characters, or any dropped, is "hidden-text": the report warns, cites of it carry a mark, and
any fact whose every citation is on such a page stays out of the rules. The 15-character floor and
the curve/image test come from sampling nine pages where a first, rectangle-only version flagged
chart labels and arrows. Full model in `docs/security.md`.

## D-028 — A captionless statement may borrow a sibling's unit (2026-10-24)

Indong Tea prints "(Amount Rs. In Lakh)" over the balance sheet and income statement but not the
cash-flow statement, so its figures could never be converted or compared. A statement without a
unit takes the unit of tables within two pages whose columns name exactly the same period dates,
only if all such tables agree and never from a table that itself borrowed; the page is recorded in
`unit_inherited_from`. A wrong scale would be worse than none, hence the three conditions. It also
raised the share of tables with a unit from about 34% to 45% on the nine older filings.

## D-029 — Diff compares figures, not prose, and ignores periods only one side has (2026-10-24)

## D-031 — Figures under misaligned headers (2026-10-26)

Ruled tables with spacer columns can print right-aligned figures up to two cells left of
left-aligned "As at ..." headers, and rows differ among themselves. A figure column with no dated
header takes the nearest dated header within two cells (the right one on a tie). Where figures sit
under their headers, behaviour is unchanged (tested). Residual risk: an unlabelled numeric column
within two cells of a dated header (a blank-headed percentage column) would be given that period.

## D-032 — Debt repayment share of the fresh issue, as a low-severity heuristic (2026-10-26)

New fact `objects.debt_repayment_amount`: the objects-table rows whose label is a repayment or
prepayment of borrowings, summed (unless one row already totals the others; a repayment made
through a subsidiary counts), and a heuristic rule that flags more than 50% of the gross fresh
issue at severity low (new `over_cap_severity`; a regulatory breach stays high). Across the
filings, LEAP India (75%), Powerica (75%) and Runwal (65%, of which 2,250 million is repayment
through two subsidiaries) are flagged; Indiqube (14%), Synoptics (14%), Shiprocket (19%) are not.
Not a regulatory limit, and repaying debt can be sensible: the flag says so in its basis. A
summed fact is verified part by part against the page (`IssueFact.parts`); a lone "repayment"
line and its "Total", or negative cash-flow lines, no longer qualify a table as an objects table.
No labels exist for this fact yet; they belong in the next held-out set.

## D-033 — Position and entity awareness in extraction and consensus (2026-10-27)

Held-out run 4 (`docs/heldout-run-4.md`, first run 54%) showed that repetition is a poor proxy for
correctness in 1,000-page filings. Decisions: (1) cover-table amounts are read by column position,
not order of appearance; (2) consensus weights front-of-document readings double, gives readings
under entity-qualified headers (excluding, standalone, subsidiary, segment, pro forma) weight 0,
and lets trusted columns be corroborated by agreeing untrusted ones; (3) a figure is kept on a
weighted lead of at least 2x, or, for size concepts only, a narrower lead when it is also the
largest figure; (4) kerned labels ("T otal") are repaired before matching. Cost: a genuine
subsidiary-only figure under a header that happens to say "subsidiary" is down-weighted, and the
front-weight assumes the issuer's own figures come first; both were true for all 18 filings but
that is a small sample. Abstention is preferred where definitions conflict (Tata Capital's PAT).

## D-034 — Bare-year headers, net operating cash flow, stub columns (2026-10-28)

Held-out run 5 (`docs/heldout-run-5.md`). (1) A header that is only a year takes the wording of
the dated header beside it, left first; never from an annual header across a quarter, which would
turn "June 2024" into a fiscal year. (2) A table that has a "net cash ... operating activities"
line ignores the "cash generated from operating activities" pre-tax subtotal. (3) A blank-headed
figure column left of the first dated header, beside a dated header column that holds figures,
stays undated. The broader rule I tried first (never lend a header to a column whose own header
column holds figures) cost two correct Veritas readings and was reverted: a blank column that
borrows a neighbour's header always produces a second reading for that period in the same table,
which is dropped as ambiguous, so the failure mode is abstention, not a wrong value. (4) Labels:
a label whose field is absent must be re-read on the cover and the summary pages before commit
(two label errors this run). Residual risk: a bare year after an unrelated dated header cell
inherits its wording.

## D-035 — Label column and dateless captions (2026-10-28)

Held-out run 6 (`docs/heldout-run-6.md`). The label column is searched among the first five cells
(was three): numeric columns never qualify, so the cost of a wider search is nil, and statements
with a serial, two blank cells and then the label are common in financial-services filings. A
dateless header cell over figures borrows the dated header in the next cell only if that dated
column holds no figures of its own; where the dated header has figures it is left alone. Residual
risk: a genuine undated column immediately left of an empty dated column would be given that date.

## D-036 — Placements are not the offer (2026-10-29)

Held-out run 7 (`docs/heldout-run-7.md`). The text patterns for the fresh issue and offer for sale
amounts may not read across "pre-IPO" or "private placement" wording: in a glossary that runs on
without sentence breaks, the placement's amount was taken as the offer for sale and then summed
into a derived total. Residual risk: other raises mentioned beside the offer (a rights issue, a
bonus) are not yet excluded; the cover-table reader, which does not use these patterns, takes
precedence where it applies.

## D-038 — Labelling tools live in the repo (2026-10-31)

The helpers used to label held-out sets (a page viewer, a label builder, a per-field comparison,
the gate script) lived in a session scratch directory that was wiped, which would have forced
every later run to rebuild them. They are now `tools/` (see `tools/README.md`): the gate script

## D-039 — A column dated against the consensus is set aside; a unit may come from the next statement (2026-10-31)

Held-out run 9 (`docs/heldout-run-9.md`). (1) When a table loses a header cell every figure sits one
period late, and a table repeated on two pages outvotes the correct reading. A (table, period)
column is now set aside when every one of its revenue, income and profit readings contradicts a
decisive consensus for its period (two or more supporters, at least double any rival); the failure
mode is a withheld figure, not a wrong one. Residual risk: a column that is correctly dated but
carries different definitions for all its anchors (a subsidiary) is also set aside, which is where
it would not be trusted anyway; a decisive consensus that is itself wrong would discard the one good
column. (2) A statement with no unit caption borrows the unit of the statement up to two pages
after it when none before it supplies one, under the same all-agree and same-dates conditions.
(3) "Public Issue" is a defined term for the total issue. Not done: guessing a unit for a table that
prints none anywhere on its page.

## D-040 — Standalone columns count when nothing else reports the figure (2026-11-01)

Held-out run 10 (`docs/heldout-run-10.md`). A column headed "standalone", "excluding ..." and the
like weighs nothing in the consensus (D-033) only when some reading of the same figure is
unqualified; a company that consolidated only from a recent year prints "(Standalone)" for the
earlier years, and those are its own figures. "Previous GAAP" and "Indian GAAP" headers are now
qualifiers (a restatement on another basis is not a rival reading). Residual risk: a filing whose
only reading of a figure is a subsidiary's would now be used; the footing and size checks still
apply. A disputed first-run label (a cover table that prints the whole issue's amount in the
fresh-issue row) was left as committed and disclosed, not changed to fit the tool.

## D-041 — The backtick is a rupee sign (2026-11-02)

Held-out run 11 (`docs/heldout-run-11.md`). Some filings' fonts print the rupee sign as a backtick;
the unit parser already read it, the issue-amount patterns did not, so a lender's abridged
prospectus lost all three issue amounts. Accepted in the fresh-issue, offer-for-sale and total
patterns. Residual risk: a backtick before a figure in running text that is not a rupee sign would
be read as one; the amount still needs a unit word (million, lakh, crore) right after it.

## D-042 — No language model anywhere; fully offline (2026-11-03)

The owner directed that all LLM support be removed so the software runs completely offline. The
`redherring.llm` package (provider protocol, cost cap, cache, schema-checked output, injection-safe
prompts; never used by the pipeline and never run against a real model) and its tests are deleted,
and nothing else imported it. `tests/test_offline.py` now fails if any module under `src/` imports
a language-model SDK or a network library, with `ingest/fetch.py` (the downloader behind
`rh ingest`) the one allowed network module. Consequences: the long tail the deterministic
extractors miss is simply withheld rather than sent to a model; the prompt-injection defence is now
structural (nothing interprets text as an instruction) as well as the existing hidden-text and
verification defences. Earlier entries D-007 and D-019 are kept as history.

## D-043 — Product aim: never silently wrong, and least time for the reader (2026-11-06)

The owner stated the needs: full accuracy, and a tool that saves people the most time. Decisions:
(1) "Full accuracy" is read as *never silently wrong*, because no extractor can promise a correct
reading of every PDF; the measure to protect is wrong values shown on held-out filings (zero on every
set since set 9's single case, which was fixed), ahead of coverage. Withholding is the safe default.
(2) Time saved is measured in pages an analyst must open: the next work is the one-page brief, a
triage view across filings, and a check-this list naming the exact page of every flagged or withheld
item, then the segmenter and text-level rules that cover what takes longest to read. (3) Extraction
coverage work continues only where a held-out set exposes a defect. (4) Before any claim of "full
accuracy" an independent human must check a sample of labels.

## D-044 — The brief restates only verified facts (2026-11-07)

`rh brief` (D-043's first item) builds its one-page brief and triage table only from what `rh analyze`
already verified: the facts that reached the rules, the flags, the rule audit, the withheld-figure
list and the hidden-text pages. It reads nothing new, so it cannot introduce a wrong figure. Ordering
(most serious first): hidden text and high flags, medium flags, low flags, withheld figures for the
latest two years, rules that could not run (grouped in one item). A figure the tables disagree on is
listed to check and never shown; growth is shown only when both years are positive. Older-year
withheld figures are counted, not listed, to keep the page short. The ranking is a first guess and
needs feedback from people who read filings.

## D-045 — An issuer-side track: due-diligence checks, DRHP builder, filing-pack check (2026-11-07)

The owner asked for a system that does the pre-filing work an investment bank and counsel do (due
diligence on financial records, legal compliance, tax, litigation and management background; drafting
the DRHP; filing with SEBI, the RoC and the exchanges). Decisions: (1) it is a second track beside the
filing reader, not a rewrite of it, and the reader remains the way to verify a finished draft. (2) It
keeps the project rules: offline, no language model, deterministic, every output sourced. A DRHP is
assembled from templates and verified data; prose a lawyer must write is left as marked gaps, never
generated. (3) The software prepares and checks; it never certifies or submits. (4) Stage 1 comes first
because stages 2 and 3 need its verified data; its design must be agreed against real DRHPs (what a
real filing discloses and how its numbers tie) before code, and it needs structured company records as
input, which are private and not in any public filing. (5) The checks are measured the way the reader
is: against filings already made, with the answers fixed before the checker runs.

## D-047 Evidence rows in the brief (plan 1.1), 2026-11-07

## D-049 Related-party check (plan 1.3): design before code, 2026-11-07

Read the related-party summaries of two filings (Leap India p.69, Fusion CX p.71). They list one row
per party and transaction (remuneration, rent, share issues, buybacks, sales, interest) with the
amount and a printed "% of revenue from operations" for each year, and no total row. Summing them
would add pay to share issues to sales, so a computed "related-party transactions as a share of
revenue" would be silently wrong; it is not built. The check will instead list rows whose
**printed** percentage of revenue for the latest full year is at or above a stated cut-off, each with
its page and row text, so nothing is computed that the document does not print. Rows for share
issues, buybacks and conversions are listed apart because they are not trading with related parties.
Before any code: label, on 10 filings, which rows are at or above the cut-off for the latest full
year (read independently with `tools/pg.py`), commit the labels, then score. Hard parts to expect:
finding the latest-year column across layouts (three or four year groups, a stub period first,
amount and percentage side by side) and rows that wrap over several lines.

Coverage found while planning: of 10 candidate filings only 5 (Leap India, Zetwerk, Fusion CX,
Orient Cables, SFC Environmental) list a "Summary of Related Party Transactions" in the contents.
The other five (Lenskart, Powerica, Vishal Mega Mart, Tata Capital, Aadhar Housing) carry the
disclosure only in the restated-statements note, which has no printed percentage of revenue. For
those the check will say "no summary table; read the note on p.N" with the page from the section map,
not compute anything. The label set therefore starts with the five filings that have a summary.

Layout survey of the five (2026-11-07), read with `tools/pg.py`: Leap India has three year groups,
latest first, one table. Fusion CX puts a three-month stub column first, then three years. SFC
Environmental has two stub columns then three years, and prints each party's rows twice (company
and consolidated views). Orient Cables has a stub then three years with the percentage header
wrapped over several lines. Zetwerk splits rows by relationship type and some of its percentages
are not a share of revenue (guarantee rows show 86% and share-based payments 69%, on other
bases), so the check must confirm that a column's header says revenue before reading it, and
withhold the page otherwise. First pass over printed percentages of 5% or more: Leap India has one
row for the latest year (purchase of plant and equipment, 12.96%, p.70); Fusion CX and Orient
Cables have none; SFC's rows need the stub-versus-year column read by hand. No extractor code
yet; the labels are the next step and will be committed before any code.

## D-053 What the offline rule allows (2026-11-07, revised the same day)

The owner's rule is **no LLM**, fully offline: "no LLM, AI is fine". An earlier version of this entry
read it more strictly (no learned component at all); that was wrong and is withdrawn. Allowed: any
machine learning that runs locally, such as the Tesseract OCR engine (a small neural network),
layout or table detectors and small classifiers, provided each is measured on labelled data before it
feeds a figure and none replaces the verification that makes a figure shown (re-read from its page,
cross-checked, withheld when in doubt). Not allowed: a language model of any kind, hosted or local,
and any cloud API; `tests/test_offline.py` enforces the model-SDK and network bans. Audit today: no
language-model SDK and no network library outside the downloader. Learned components in use: optional
OCR only. The README says "no language model". The fixed goals are in `CHARTER.md` and the
startup-readiness gaps and their order are in `plan.md`. Where a small local model would save a
person more time than rules can (for example finding tables in scanned pages), it may now be used
under the measurement rule above.

## D-056 Related-party check, first version (2026-11-12)

## D-059 Release 0.3.0: one system, not two side by side (2026-11-13)

- **`ipo run FILE.pdf`** (plan 4.1) chains add, parse, analyze, brief and report for one PDF. The doc
  id comes from the file name; the same file can be run again; a different file under a used id is
  refused. Alternative considered: a separate fast path that skips the manifest. Rejected, because

- **One home page** (plan 4.2): `data/reports/index.html` is the triage table with links to each brief
  and full report. The separate report index and `triage.html` were removed as duplicates.
- **The reader inside the web app** (first step of Phase 5): `reader_service` runs the reader on an
  upload in a single background worker, caches by content hash and reader version, and the document
  page shows it as a tab. It is read-only and separate from case data on purpose: the eligibility

- **Coherence**: the command is `ipo` only (the `rh` alias was a leftover of the old name); the API
